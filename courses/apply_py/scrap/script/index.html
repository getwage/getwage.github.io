    网络爬虫训练¶

    一、接入的两种方式： requests 与 urllib.request 的区别¶

    这两个库都是 Python 中用于发送 HTTP 请求的工具，但它们在设计理念、易用性和功能丰富度上有显著差异。

    定位与背景¶

    • urllib.request：Python 标准库的一部分，无需额外安装，开箱即用。它是 Python 内置的底层 HTTP 客户端模块。
    • requests：第三方库，需要通过 pip install requests 安装。它的口号是 "HTTP for Humans"，旨在让 HTTP 请求变得简单直观。

    代码对比：同一个 GET 请求¶

    使用 urllib.request¶

    import urllib.request
import json

url = "https://api.example.com/data"
req = urllib.request.Request(url, headers={"User-Agent": "MyApp/1.0"})

try:
    with urllib.request.urlopen(req) as response:
        data = json.loads(response.read().decode('utf-8'))
        print(data)
except urllib.error.HTTPError as e:
    print(f"HTTP错误: {e.code}")
except urllib.error.URLError as e:
    print(f"URL错误: {e.reason}")

    使用 requests¶

    import requests

url = "https://api.example.com/data"
response = requests.get(url, headers={"User-Agent": "MyApp/1.0"})

if response.status_code == 200:
    data = response.json()  # 自动解析JSON
    print(data)
else:
    print(f"请求失败: {response.status_code}")

    核心差异对比¶

    对比维度 urllib.request requests
    安装 标准库，无需安装 需 pip install requests
    代码简洁度 冗长，需手动处理编解码 极简，链式调用
    JSON解析 需手动 json.loads(response.read().decode()) 直接 response.json()
    异常处理 需区分 HTTPError 和 URLError 统一用 response.raise_for_status()
    Session管理 较繁琐 requests.Session() 一行搞定
    Cookie处理 需配合 http.cookiejar 模块 自动管理，session.cookies 直接访问
    文件上传 需手动构造 multipart 表单 files={'file': open('a.txt', 'rb')} 一行搞定
    超时设置 支持但语法不够直观 timeout=5 简洁明了
    重试机制 需自行实现 配合 urllib3 的 Retry 类可轻松实现
    认证支持 需手动构造 Authorization 头 内置 auth=(user, pass) 和多种认证方式
    SSL验证 支持但配置复杂 verify=True/False 一行控制

    何时选择哪个？¶

    选 requests（推荐绝大多数场景）¶

    • 日常开发、数据采集、API 调用
    • 需要频繁处理 JSON、Cookie、Session
    • 追求代码可读性和开发效率
    • 项目中已经使用了其他第三方库，不介意多一个依赖

    选 urllib.request¶

    • 编写无外部依赖的脚本（如某些受限环境只能使用标准库）
    • 学习 HTTP 底层原理（它更"裸露"，有助于理解请求的本质）
    • 极简工具脚本，不想额外安装包

    二、使用urllib.request 和BeautifulSoup¶

    from urllib.request import urlopen
html = urlopen('http://www.getwage.xyz/index.html')
print(html.read())
    如果同时调入BeautifulSoup进行页面解析，可以如下方法获得H1标题： 
    from urllib.request import urlopen
from bs4 import BeautifulSoup
html = urlopen('https://www.getwage.xyz')
bs = BeautifulSoup(html.read(), 'html.parser')
print(bs.h1)

    面对复杂的Html,有时需要进行异常处理 

    from urllib.request import urlopen
from urllib.error import HTTPError
from bs4 import BeautifulSoup
def getTitle(url):
    try:
        html = urlopen(url)
    except HTTPError as e:
        return None
    try:
        bsObj = BeautifulSoup(html.read(), "lxml")
        title = bsObj.body.h1
    except AttributeError as e:
        return None
    return title
title = getTitle("http://www.pythonscraping.com/pages/page1.html")
if title == None:
    print("Title could not be found")
else:
    print(title)

    三、 Parsel 与 BeautifulSoup 应用区别详解¶

    Parsel 和 BeautifulSoup 都是 Python 中用于解析 HTML/XML 文档的库，但它们在设计理念、性能表现和适用场景上有明显差异。

    定位与背景¶

    • BeautifulSoup（bs4）：老牌 HTML 解析库，社区庞大、文档丰富，支持多种底层解析器（html.parser、lxml、html5lib），以 API 简洁直观著称，适合快速开发和团队协作。
    • Parsel：由 Scrapy 框架团队开发，底层基于 lxml（C 语言实现），是 Scrapy 的核心解析引擎，但也可独立使用。它同时支持 CSS 选择器、XPath 和正则表达式三种解析模式，性能更强。

    代码对比：同一个提取任务¶

    假设要抓取以下 HTML 中的标题和链接：

    <div class="news-list">
    <ul>
        <li><a href="/news/1">新闻一</a><span>2026-06-01</span></li>
        <li><a href="/news/2">新闻二</a><span>2026-06-02</span></li>
    </ul>
</div>

    BeautifulSoup 写法¶

    from bs4 import BeautifulSoup

soup = BeautifulSoup(html, 'lxml')
results = []
for li in soup.select('div.news-list ul li'):
    title = li.select_one('a').text
    link = li.select_one('a')['href']
    date = li.select_one('span').text
    results.append({'title': title, 'link': link, 'date': date})

    Parsel 写法¶

    from parsel import Selector

sel = Selector(text=html)
results = []
for li in sel.css('div.news-list ul li'):
    title = li.css('a::text').get()
    link = li.css('a::attr(href)').get()
    date = li.css('span::text').get()
    results.append({'title': title, 'link': link, 'date': date})

    核心差异对比¶

    对比维度 Parsel BeautifulSoup
    底层引擎 lxml（C 扩展） 可选 html.parser / lxml / html5lib
    解析速度 更快（C 语言实现，比 bs4 快 3-5 倍） 略慢（纯 Python API 层有额外开销）
    选择器支持 CSS + XPath + 正则，三者可混合使用 主要用 CSS Selector，XPath 需配合 lxml
    API 风格 链式调用，.css() / .xpath() 返回 SelectorList 面向对象，.find() / .find_all() / .select()
    异常安全 .get(default='xxx') 自动处理 None 需手动 try-except 或判断 if tag:
    正则集成 .re() / .re_first() 直接在选择器上调用 需 import re，单独调用 re.search()
    内存占用 较低（流式解析优化） 较高（全文档加载到内存）
    社区生态 较小，但 Scrapy 用户天然使用 非常活跃，教程和第三方插件丰富
    学习曲线 中等（需了解 XPath 语法） 低（API 非常直观）

    各自动手亮点¶

    Parsel 的独特优势¶

    • 链式选择器：可以连续 .css().css().xpath() 嵌套，代码更清晰。
    • 智能提取：.get(default='xxx') 自动处理元素不存在的情况，无需 try-except。
    • 正则直接嵌入：.css('.price::text').re_first(r'\d+\.\d+') 一行搞定提取+匹配。
    • CSS 与 XPath 混用：同一文档中可自由切换两种语法，灵活应对复杂结构。
    • Scrapy 无缝衔接：如果未来项目升级到 Scrapy 框架，Parsel 代码几乎无需改动。

    BeautifulSoup 的独特优势¶

    • API 极简：.find('div', class_='xxx') 语法接近自然语言，新手友好。
    • 解析器可选：不依赖 lxml，纯 Python 的 html.parser 也能工作，适合受限环境。
    • 容错性强：对不规范 HTML 的容忍度极高，能自动修复缺失的闭合标签等问题。
    • 社区资源丰富：遇到问题时，搜索到的解决方案更多。

    选型建议¶

    项目场景 推荐选择
    快速原型、小型脚本、新手入门 BeautifulSoup
    大规模抓取、性能敏感、复杂嵌套结构 Parsel
    已使用 Scrapy 框架 Parsel（天然集成）
    受限环境（不能装第三方 C 扩展） BeautifulSoup + html.parser
    混合使用 简单页面用 bs4，复杂页面用 Parsel

    混合使用¶

    两者并非互斥关系，实际项目中完全可以混合使用：用 BeautifulSoup 做初步的粗粒度定位，再将子片段交给 Parsel 做精细提取。例如：

    from bs4 import BeautifulSoup
from parsel import Selector

# bs4 快速定位大块区域
soup = BeautifulSoup(html, 'lxml')
section = soup.find('div', class_='main-content')

# 转给 Parsel 做精细提取
sel = Selector(text=str(section))
title = sel.xpath('.//h1/text()').get()
tags = sel.css('.tag::text').getall()

    这样既利用了 bs4 的容错性，又享受了 Parsel 的高效提取能力。
